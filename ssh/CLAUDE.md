# SSH Config

SSH settings use `ssh/config.d/` fragments with SSH's native `Include` directive. See [doc/architecture.md](../doc/architecture.md#ssh-configuration) and [ADR 0026](../doc/adr/0026-versioned-ssh-config-with-config-d.md).

## Fragments

| File                              | Versioned       | Purpose                                                                             |
| --------------------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `ssh/config.d/auth`               | yes             | agent-session key override + `Host *` 1Password IdentityAgent                       |
| `ssh/config.d/agent-relay`        | yes             | agent-session SSH -> localhost SOCKS5 relay (sandbox port-22 workaround)            |
| `ssh/config.d/agent-mux`          | yes             | agent-session connection sharing (ControlMaster) in its own socket dir, macOS only  |
| `ssh/config.d/term`               | yes             | `Host *` default `TERM=xterm-256color`                                              |
| `~/.ssh/config.d/hosts`           | no (gitignored) | per-host overrides                                                                  |
| `~/.ssh/config.d/colima`          | no (gitignored) | generated by `sshconfig.sh` if colima installed                                     |
| `config/ssh/authorized_keys.home` | yes             | list of 1Password item titles synced into `~/.ssh/authorized_keys` (home role only) |

## Common Tasks

**Add a per-host TERM override:**

1. Check what's available on the remote: `toe -a | grep xterm-direct`
2. Add a `Host` block to `~/.ssh/config.d/hosts`:
   ```
   Host example.com
     SetEnv TERM=xterm-direct
   ```

**Re-run setup after changes:**

```bash
./sshconfig.sh
```

## Agent-Session Key Override

`ssh/config.d/auth` has `Match exec` blocks before `Host *`, keyed on `$CLAUDECODE` (every Claude Code session) or `$AGENT_SESSION` (other harness wrappers, e.g. prime-agent) plus `$DOTPICKLES_ROLE`. In an agent session ssh offers the Keychain-loaded per-role agent key (`~/.ssh/agents/<role>/id_ed25519`) instead of 1Password, so there's no TouchID prompt. It only picks which key to offer; the target still has to authorize that key. See [ADR 0031](../doc/adr/0031-role-scoped-agent-git-identity.md), [ADR 0030](../doc/adr/0030-ssh-keychain-loading-at-login.md).

## Agent-Session SSH Relay

The command sandbox denies outbound port 22 but allows localhost. In agent sessions only, `ssh/config.d/agent-relay` sends every SSH connection through a local SOCKS5 proxy (`ProxyCommand /opt/homebrew/bin/ncat --proxy 127.0.0.1:1080 --proxy-type socks5 %h %p`, full path because launchd children don't share the shell's PATH). `%h`/`%p` pass the real host through, so `known_hosts` matches normally. Outside an agent session SSH goes direct. `home` and `work` both use it; why SSH instead of HTTPS, and each layer's job, are in [ADR 0055](../doc/adr/0055-agent-git-over-ssh-through-the-relay.md). A `work`-role push through the relay is still unverified (bean dotfiles-11qr).

The other end is the `com.technicalpickles.agent-ssh-relay` LaunchAgent running `gost`, limited to the host:port allowlist in `config/gost/agent-ssh-relay.yml`. Any host an agent needs to SSH into (git remotes, admin targets like `picklelab:22`) needs a `<host>:22` line there; nothing else changes. Tailnet nodes are covered by one `*.tail2023b7.ts.net:22` wildcard (port 22 only); MagicDNS short names like `picklelab` don't match it and keep their own lines. A CIDR matcher can't carry a port in gost, so tailnet IPs (`100.64.0.0/10`) are deliberately not allowlisted: that would open every port on every node.

Coder workspaces (`<workspace>.coder` via Coder Connect) are the exception. Those names only resolve through macOS split DNS, and gost's pure-Go resolver skips it (`lookup ... on 127.0.2.2:53: no such host` in `/tmp/com.technicalpickles.agent-ssh-relay.out`). So `agent-relay` has a `Match host *.coder` block that passes `--proxy-dns local` to ncat, and the YAML allowlists Coder's fixed tailnet prefix `fd60:627a:a42b::/48` rather than names.

`sshconfig.sh` links `auth` and `agent-relay` only on macOS, and removes them elsewhere. Linux hosts (Coder workspaces run with the sandbox off) don't need them, and their escaped quotes (`\"`) inside `Match exec "..."` make Ubuntu 24.04's OpenSSH 9.6 reject the whole config with `Bad Match condition`, breaking every ssh command. Keep that in mind before linking any fragment with `Match exec` cross-platform.

- Status: `./launchagents.sh status com.technicalpickles.agent-ssh-relay`
- Reload after a YAML edit: `launchctl kickstart -k gui/$(id -u)/com.technicalpickles.agent-ssh-relay` (unsandboxed; `launchctl` is blocked in the sandbox)
- A missing host fails as `Ncat: Error: connection not allowed by ruleset.` then `kex_exchange_identification: Connection closed by remote host`. That means add it to the YAML and reload, not a key or sandbox problem.

## Agent-Session Connection Sharing

Every new ssh connection signed by Automic Vault's agent takes about 13s, auto-approved or not (measured 2026-11-18: `ssh picklelab true` 13.6s three times, `git@github.com` 14s; `ssh -v` shows the gap between "Server accepts key" and "Authenticated"). `just deploy-openclaw` in picklehome opens about 10 connections, so about 2 minutes of its 11 were auth. `ssh/config.d/agent-mux` makes agent sessions share one connection per host: `ControlMaster auto`, `ControlPath ~/.ssh/cm-agent/%C`, `ControlPersist 5m`. The first connection pays the 13s; later ssh/scp to the same host took 0-1s in testing.

- **Agent sessions only, own socket directory.** A master opened from a human terminal must not be reachable from an agent session, or the agent could reuse a connection to a host outside the relay allowlist. Humans get no multiplexing from this fragment. Whether a plain terminal is also slow is unmeasured, so a human-side fragment is deferred.
- **Audit trail.** Multiplexed sessions don't go through the ssh-agent, so `av history` shows one entry per master, not per use.
- **Short paths.** A unix socket path is limited to about 104 bytes and `%C` is 40 characters. The default `$TMPDIR` in the sandbox is too long (`too long for Unix domain socket`).
- **Stuck connection:** `ssh -O exit <host>` with the same ControlPath, or `rm ~/.ssh/cm-agent/*`.
- **macOS only**, for the same `Match exec` quoting reason as `auth` and `agent-relay`. `sshconfig.sh` creates `~/.ssh/cm-agent` (mode 700); ssh won't.
- **Git over ssh** goes through the same config only when `GIT_SSH_COMMAND=ssh` (see below); unverified whether git pushes benefit.

## The `GIT_SSH_COMMAND` Conflict

Under the sandbox, Claude Code injects its own `GIT_SSH_COMMAND` into every Bash call, pointing at a harness proxy that refuses SSH. Git resolves that ahead of `core.sshCommand` and `ssh_config`, so it bypasses the relay and fails as `ssh_dispatch_run_fatal: Connection to UNKNOWN port 65535: Broken pipe`. That is not a missing `allowedDomains` entry, which fails as `SOCKS error 2` on :443. The fix is the `SessionStart` hook in `claude/roles/home.jsonc` that appends `export GIT_SSH_COMMAND=ssh` to `$CLAUDE_ENV_FILE`; setting it in the role `env` block loses to the injection. If the broken pipe comes back after a CLI upgrade, check `env | grep GIT_SSH_COMMAND` first, and use `GIT_SSH_COMMAND=ssh git ...` per command meanwhile. Full story and dead ends: ADR 0055, upstream [anthropics/claude-code#70684](https://github.com/anthropics/claude-code/issues/70684).

## Inbound SSH (being SSH'd into, e.g. over Tailscale)

**On the target machine (home role only):**

1. Turn on Remote Login manually: `System Settings → General → Sharing → Remote Login` -- this is a system security setting `sshconfig.sh` deliberately doesn't touch, it only detects and warns if it looks off.
2. `./sshconfig.sh` syncs `~/.ssh/authorized_keys` from the 1Password item titles listed in `config/ssh/authorized_keys.home` (vault `Personal`). Add a new personal identity by adding its item title to that file and re-running.

`config/ssh/authorized_keys.home` is a separate list from `config/1password/agent.toml.<role>` below even though today's entries overlap: the agent allowlist is _outbound_ (which keys 1Password offers as this machine's identity), `authorized_keys.home` is _inbound_ (who's allowed to log in as this user).

## 1Password SSH Agent Allowlist

> On Automic Vault machines, `~/.ssh/config` starts with an `av`-managed block that sets `IdentityAgent` to `~/.local/share/automic-vault/ssh-agent.sock` for all hosts, ahead of everything below, so agent ssh runs without 1Password approval. This section describes the 1Password path. AV signing and key lifecycle: [ADR 0059](../doc/adr/0059-automic-vault-for-git-signing-and-agent-ssh.md).

`Host *` in `ssh/config.d/auth` points at the 1Password agent. By default 1Password offers every key in the unlocked vault. Per-role allowlists live at `config/1password/agent.toml.<role>` and are symlinked to `~/.config/1Password/ssh/agent.toml` by `sshconfig.sh` based on `$DOTPICKLES_ROLE`. See [ADR 0033](../doc/adr/0033-1password-ssh-agent-allowlist.md).

To check what 1Password is currently offering:

```bash
SSH_AUTH_SOCK="$HOME/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock" ssh-add -l
```

## Important

- Edit `ssh/config.d/auth` and `ssh/config.d/term` for versioned changes
- `~/.ssh/config.d/hosts` is machine-local and gitignored; recreate it per machine
