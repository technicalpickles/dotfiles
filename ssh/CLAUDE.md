# SSH Config

SSH settings use `ssh/config.d/` fragments with SSH's native `Include` directive. See [doc/architecture.md](../doc/architecture.md#ssh-configuration) and [ADR 0024](../doc/adr/0024-versioned-ssh-config-with-config-d.md).

## Fragments

| File                              | Versioned       | Purpose                                                                             |
| --------------------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `ssh/config.d/auth`               | yes             | agent-session key override + `Host *` 1Password IdentityAgent                       |
| `ssh/config.d/term`               | yes             | `Host *` default `TERM=xterm-256color`                                              |
| `~/.ssh/config.d/hosts`           | no (gitignored) | per-host overrides                                                                  |
| `~/.ssh/config.d/colima`          | no (gitignored) | generated by `sshconfig.sh` if colima installed                                     |
| `config/ssh/authorized_keys.home` | yes             | list of 1Password item titles synced into `~/.ssh/authorized_keys` (home role only) |

## Common Tasks

**Add a per-host TERM override:**

1. Check what's available on the remote: `toe -a | grep xterm-direct`
2. Add a `Host` block to `~/.ssh/config.d/hosts`:
   ```
   Host example.com
     SetEnv TERM=xterm-direct
   ```

**Re-run setup after changes:**

```bash
./sshconfig.sh
```

## Agent-Session Key Override

`ssh/config.d/auth` also has `Match exec` blocks, keyed on `$CLAUDECODE` (set by every Claude Code session) and `$DOTPICKLES_ROLE`, that come before `Host *`. When both are set, ssh uses the Keychain-loaded per-role agent key (`~/.ssh/agents/<role>/id_ed25519`) over fish-ssh-agent instead of 1Password -- no interactive TouchID, and it applies to any host without per-host config. Outside an agent session, `Host *` still routes through 1Password as normal. See [ADR 0031](../doc/adr/0031-role-scoped-agent-git-identity.md) and [ADR 0030](../doc/adr/0030-ssh-keychain-loading-at-login.md).

This only helps once the agent key's public half is authorized on the target host (`~/.ssh/authorized_keys`) -- it doesn't grant access, it just picks which already-known key to offer.

## Inbound SSH (being SSH'd into, e.g. over Tailscale)

**On the target machine (home role only):**

1. Turn on Remote Login manually: `System Settings → General → Sharing → Remote Login` -- this is a system security setting `sshconfig.sh` deliberately doesn't touch, it only detects and warns if it looks off.
2. `./sshconfig.sh` syncs `~/.ssh/authorized_keys` from the 1Password item titles listed in `config/ssh/authorized_keys.home` (vault `Personal`). Add a new personal identity by adding its item title to that file and re-running.

`config/ssh/authorized_keys.home` is a separate list from `config/1password/agent.toml.<role>` below even though today's entries overlap: the agent allowlist is _outbound_ (which keys 1Password offers as this machine's identity), `authorized_keys.home` is _inbound_ (who's allowed to log in as this user).

## 1Password SSH Agent Allowlist

`Host *` in `ssh/config.d/auth` points at the 1Password agent. By default 1Password offers every key in the unlocked vault. Per-role allowlists live at `config/1password/agent.toml.<role>` and are symlinked to `~/.config/1Password/ssh/agent.toml` by `sshconfig.sh` based on `$DOTPICKLES_ROLE`. See [ADR 0033](../doc/adr/0033-1password-ssh-agent-allowlist.md).

To check what 1Password is currently offering:

```bash
SSH_AUTH_SOCK="$HOME/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock" ssh-add -l
```

## Important

- Edit `ssh/config.d/auth` and `ssh/config.d/term` for versioned changes
- Never edit `~/.ssh/config` directly -- it's managed by `sshconfig.sh`
- `~/.ssh/config.d/hosts` is machine-local and gitignored; recreate it per machine
- Never edit `~/.config/1Password/ssh/agent.toml` directly -- edit `config/1password/agent.toml.<role>` instead
